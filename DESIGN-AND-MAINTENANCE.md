# Routines: design and maintenance guide

## Source of truth and design intent

`web/index.html` is the editable screen, styles, translations, scheduling logic and browser-side bridge. The native shell loads a generated copy, `src/web.js`; do not edit that generated file. After every web change run `node scripts/make-web.js`, then `node scripts/check-project.js` and the applicable tests below. GitHub Actions also runs the generation step.

Update 17 uses the supplied **Apple Developer Support** page as a visual reference, not as functional app code. Its body uses 17px/25px text, -0.022em letter spacing, #1d1d1f on white, #0066cc links and #0071e3 blue button fill. At a 390px viewport its main content is 87.5% wide (24.375px side margins) and its mobile hero heading is 32px/36px, weight 600. Its hero background is #e8ecf1, with a blue-tinted gradient elsewhere. The final CSS block maps these values to Routines; controls and spacing that have no equivalent on the Support page are app-specific. It is not a pixel-identical copy of the site, and it does not copy Apple's branding, imagery, or web navigation. Dark mode is an app-specific adaptation, not copied from that light reference. The New Day button uses white text on dark gold in dark mode for contrast, while retaining its yellow sun; its light-mode version stays yellow with dark text. The supplied System Status page uses a 16px #28c940 circle and its update note is 14px/1.5, -0.01em, #595858. Routines adds a white tick to that circle next to Up for and previously used the note style for a time-zone footer; Update 20 removes that footer.

The reference's SF Pro/SF Pro Icons stylesheet URL is recorded in the HTML comment: `https://www.apple.com/wss/fonts?families=SF+Pro,v3|SF+Pro+Icons,v3`. It is not requested at runtime. Apple says not to bundle SF Pro files in an app and recommends `system-ui` for the WebKit system font: https://developer.apple.com/documentation/technologyoverviews/fonts . On iOS this selects the system's San Francisco family with appropriate optical and language variants; other platforms can render differently. Apple provides SF Pro files for design mockups at https://developer.apple.com/fonts/ under its license; do not embed or redistribute those files without appropriate permission.

CSS contains historical overrides. The last “Apple Developer Support reference” block deliberately wins where it has equal or greater specificity. Search for a selector and inspect computed styles before changing an older block. Key variables: `--page` is the list background; `--bg` the sheet surface; `--bg2`/`--bg3` control surfaces; `--ink*` text; `--line*` dividers; `--y` is the legacy name for primary **blue**, not yellow; `--font` and `--display` use the WebKit system font with local fallbacks; on iOS the system chooses the appropriate San Francisco variant. Status colors remain semantically distinct: green done, orange late, red missed/destructive. The 58px header is tied to the sticky timeline's top offset; change both together. Safe-area variables keep content clear of device cutouts.

See `FUNCTION-MAP.md` for grouped function responsibilities and risks.

## Project map

- `web/index.html`: view markup, style cascade, language strings, model, interactions, and native notification plans. Markup IDs and `data-*` selectors are JS hooks. `#sheet .sbody` scrolls vertically; header and Save remain outside it. Preserve that structure and test small screens, long translations and the keyboard.
- `App.js`: Expo/React Native shell, WebView lifecycle, bridge dispatch, permissions, app-state handling, imports/exports and system UI. It seeds the page only after native storage loads. On background it asks the page to flush both storage and reminders; on time-zone change it reloads the page.
- `src/shim.js`: injects initial storage and a localStorage bridge before the page's script runs. Revisions help reconcile native and WebView copies. Its escaping protects JSON embedded in script text. Changing order or message format can lose data.
- `src/store.js`: native two-copy storage with revisions and retry on write failure. `routines-meta.json` holds separate app metadata. Test migration, restart, interrupted writes and import/export when touching it; two copies reduce risk but do not guarantee recovery.
- `src/notify.js`: reconciles the web page's desired local-notification plan with the OS, with iOS capacity limits, permission checks, notification identifiers, response actions and badge updates. The OS controls actual delivery; foreground/background/locked-device tests are essential.
- `src/web.js`: generated string of `web/index.html`, recreated by `scripts/make-web.js`. Never hand-edit it.
- `index.js`: Expo entry point. `scripts/make-web.js`: bundles the HTML; `scripts/check-project.js` checks syntax and generator consistency; `scripts/test-schedules.js` runs deterministic recurrence cases against functions read from the real page.
- `app.json`: app identity, icons, OS permissions and Expo plugins. `eas.json`: build/submit profiles. `package.json`: dependencies and commands. These are strict JSON; comments in them would break parsing. Document changes here instead.
- `.github/workflows/main.yml`: the previously supplied cloud workflow; the actual current repository was not available for comparison. Its secrets are configured in GitHub, not included here. Do not print secrets or replace signing settings blindly.
- `assets/`: app and notification images; keep file paths in `app.json` synchronized. `privacy.html`: standalone policy; review accuracy if data practices change. `.gitignore` avoids uploading builds, dependencies and private signing keys. `START-HERE.md`: user-facing handoff.

## Rules and side effects to preserve

- `norm()` and migration blocks keep older saved/exported tasks usable. Inspect an actual backup before changing task fields. `iso`, `parse`, `addDays`, `addMonths`, `step`, `nextFixed` and `firstOnOrAfter` work with local calendar dates; changing them changes both display and notification timing, particularly around DST and end-of-month. `nextFixed` jumps close to the correct occurrence, so old daily anchors are not truncated at 5,000 repeats; retain the calendar/DST and end-of-month checks.
- Scheduled hourly and one-day tasks require a time or a confirmed after-waking duration. Scheduled longer day/week/month repeats have a start date and optional removable time. Flexible goals hide those scheduled controls. `formValid()` controls disabled state and the Save handler checks again. Old tasks are not silently converted during import.
- Future scheduled tasks, including hourly/daily starts and distant dates, render directly in the list rather than being filtered out or hidden behind a Later disclosure. They retain their actual due dates. Clock-change recovery must not reinterpret a future initial anchor as accidental clock drift; hourly wake routines must not be started early by roll().
- The dashboard no longer shows the time-zone footer. `wakeCheck` is decorative and is visible only when the Up for counter has a wake value. Neither affects task completion.
- Update 18 replaces the WebKit date/time picker with one shared custom dialog. Hidden `data-pick-kind` inputs retain the canonical YYYY-MM-DD/HH:MM values expected by scheduling. `syncPickerFields` builds visible buttons (except the task-time draft `wInput`, whose trigger is Add time); `cpOpen`, `cpDraw` and `cpClose` manage a temporary draft, with Set committing via input/change events and Cancel leaving the value alone; for task time, `addPickedTime()` also updates the editor draft after Set. `lDate.min` limits dates for Later. The MutationObserver restores triggers after editor/wake rerenders; sync is idempotent to avoid an observer loop. Test all five inputs, background refresh, accessibility, time zone and 12/24-hour settings after changes. The after-waking duration wheel is **custom web UI**, not a native UIDatePicker. `F.wakeDraft` is tentative; `F.wake` becomes valid when Set duration is tapped. Values are capped at 18 hours. Test scrolling, tap, keyboard and VoiceOver on a real device before altering row height or snap behavior.
- `advance` saves schedule state in `prev` before clearing `laterDate`; `restore` must restore that date when the most recent completion is undone. Hourly same-day snapshots also keep a bounded `prev.parent` chain so the most recent checks can be undone in sequence. Older backups may not contain these fields.
- `openSheet` creates draft `F`; `paintSheet` rebuilds editor controls and relies on delegated events; Save is the point that changes the task. Existing anchor and next due date are intentionally preserved when an unchanged task is saved. Dates in rows and notification plans must continue to agree.
- The page and shell communicate through `ReactNativeWebView.postMessage` and `window.__nat` callbacks. Search both sides before renaming a message or changing its payload. Data persists locally; exports may be shared by the user.
- Do not infer sleep merely from inactivity; existing prompts and user confirmation have distinct roles. Check wake-up behavior across midnight, time zones, DST, app relaunch and notifications before changing it.

## Verification and release

Run `node scripts/make-web.js`, `node scripts/check-project.js`, and `node scripts/test-schedules.js`. The latter checks recurrence arithmetic in three time zones; it does not test the full app. For automated browser regressions, install Playwright and Chromium separately and run `node scripts/test-ui.cjs`, `node scripts/test-future.cjs`, `node scripts/test-editor19.cjs` and `node scripts/test-editor20.cjs` (or set CHROMIUM_PATH to your browser); these use synthetic test data only. Also run interactive tests for create/edit/delete, flexible and scheduled repeats, dates, wake-up, Later, dark/light, 12/24-hour, French/Arabic RTL, narrow screens and restore from a real backup. Check pending reminders, badge, persistence, keyboard, accessibility, and custom pickers on an actual iPhone, including locked/background use. Browser checks cannot prove native build, notification delivery, accessibility behavior, or crash-free operation. Back up and compare the real GitHub repository and workflow before replacing files. Test a TestFlight build before submission.

## Update 18 regression notes

The custom pickers have been exercised in Chromium for starting date, task time, wake time, completion time and Later; light/dark, English/French/Arabic and narrow widths were checked. Calendar and clock values are centered explicitly because global button styles otherwise left-align them. Tests cover committing/canceling, 12-hour noon/midnight, future tasks after restart, completion/uncompletion and import Undo. `test-schedules.js` checks 100,000 generated fixed recurrences in each of three time zones, including an old-anchor check. These tests do not establish iPhone WebKit, VoiceOver, native notification, build or release behavior. French and Arabic picker, completion and overdue wording was reviewed in context; this is not a full professional localization audit.

## Update 19 regression notes
Past anchors are accepted and kept across reload, the task-time picker has a single confirmation, the hourly mode selector is hidden, and the editor fade tracks remaining scroll content. Targeted French and Arabic task-editor wording and Arabic quota agreement were improved; other translations still need native-speaker review. The tests do not replace an actual iPhone build and device test.

## Update 20
The editor groups name and notes, and the date picker uses a minimal round selection inspired by the supplied Apple screenshots. The recurrence summary now scrolls with the task form; validation and Save stay fixed. Add time always has AM/PM while the rest of the app retains the chosen 12/24-hour display. Confirm scroll clearance, touch tint, VoiceOver and picker behavior on an actual iPhone.
