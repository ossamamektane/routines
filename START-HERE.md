# Routines — Update 36: native React migration, first step

The task-actions menu (three dots beside a task) is now a React Native bottom sheet, using Bills’ shared-value native spring and closing timing. Travel extends offscreen to prevent tall sheets peeking on smaller phones. It uses Bills’ Ionicons, dark/light palette and a compact bottom inset. Actions still use the existing tested Routines task engine. Other screens and sheets—including Add/Edit, settings, wake and catch-up—remain WebView-based. This is **not a complete React Native conversion**, nor an exact match for the rest of Bills.

The previous launch crash is still **undiagnosed**. This version adds a native React component and `@expo/vector-icons`; it has NOT been built or run on an iPhone. Treat it as an experimental TestFlight candidate, not a verified fix. The build workflow installs the additional icon dependency. Check launch, task menu opening/closing, actions, dark mode, VoiceOver, Reduced Motion, small screens and the home indicator on a real phone. Browser tests simulate the native bridge but do not test the native UI or native animation.

Notification sounds already use the system default; there was no louder sound change to undo. The reported delivery problem remains undiagnosed: mocked planning and scheduling pass, but device delivery, permissions, sound and lock-screen behavior need an actual iPhone test. The planner schedules roughly 50 hours ahead and hourly wake-dependent tasks require New Day.

**Do not uninstall the existing app:** iOS may delete locally stored tasks. Back up the repository and preserve secrets and signing settings. Extract this ZIP into the repository root including `.github/workflows/main.yml`, then use the existing build/submission workflow. Install the TestFlight build as an update to the same bundle ID, not a delete/reinstall. Back up your tasks from inside the app once it opens.

Test launch, saved tasks, sheet position and keyboard on iPhone before relying on the build. For reminders, enable Task reminders in the app and notifications in iPhone Settings, then schedule a task a few minutes ahead and test with the phone locked. If launch still crashes or reminders do not arrive, provide the crash report/build number and the time, task type, app state and notification settings. Browser and mocked-OS tests cannot prove iOS launch or delivery.
